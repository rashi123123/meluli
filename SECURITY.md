# Security reporting

Only the latest release receives fixes. Meluli is maintained by one person, and no response time is guaranteed.

Please do not post vulnerabilities involving private data in public issues. Use the repository's **Security → Report a vulnerability** option. If it is unavailable, open a minimal issue asking for a private reporting channel without disclosing exploit details, personal recordings, transcripts or secrets.

Include the affected version, macOS version, reproduction steps and impact. Use synthetic or public test material. Do not access other people's data to demonstrate a problem.

Recordings and transcription must stay on the local machine. Model downloads and link imports require network access. A change that sends audio or transcripts to a remote service must not be introduced as a silent fallback. Actions (flows) are the one exception, and only by the user's choice: they send text, never audio, only to a host the user approved for that connection, and redirects are refused.

The repository does not currently offer a bug bounty.
